=============================== NOTES FOR THE IMPLEMENTER (not sent) ===============================
Sent as the second user text block, after prompt-v2.txt (the first block, with cache_control: ephemeral),
exactly as v1's sharpenAI() and lib/ai.mjs complete() do today. Model and tier stay the same
(quick: claude-sonnet-5-5 at effort "low"); output_config.format = schema-v2.json.

Placeholders ({{#x}}…{{/x}} = only when x is non-empty; {{^x}}…{{/x}} = only when x is empty):
  voice  voiceBlock({ ...voice, never: null }), as in v1. Omit the block when there is no voice profile.
  never  the never-say list, deduped, trimmed, each <= 60 chars, at most 40, joined with ", ".
  keep   the put-back list, deduped, trimmed, each <= 60 chars, at most 20, joined with ", ".
  line   the first line of the post: leading whitespace dropped, cut at the first "\n", trailing
         whitespace dropped, runs of spaces/tabs collapsed to one, every <line>, </line>,
         <rest_of_post> and </rest_of_post> tag removed (case-insensitive, spaces allowed inside
         the brackets), capped at SHARPEN.AI_MAX (1000) code points. A longer line never reaches
         Claude: the server sends it to the engine (reason 'long'), as in v1.
  rest   everything after the first "\n", only when it has non-space text: same tag stripping,
         3+ newlines collapsed to 2, trimmed, capped at 1200 code points (cut back to the last
         space and end with "…"). It is context only: SHARPEN.fromClaude checks every fact and
         word against the line alone, so a fact pulled up from the rest is rejected ('fact added'
         or 'added word').
  more   true when the client says the post goes on but did not send its text (the v1 `more`
         flag). Then "The post goes on after this line." replaces the rest block.

Two server-side changes go with the template:
  1. Skip Claude when SHARPEN.tooThin(text) is true (gibberish, under three real words, only a
     disclaimer) and answer with the engine's sharpenLine(): v1 spent 21 Claude calls on such lines
     only for the validator to say 'thin' and show the identical engine line.
  2. Pass the same `text` (line + rest) to SHARPEN.fromClaude, so the 280 check sees the whole post.
